# BRD-003 新行为挂 feature flag，默认关

- 状态：已定稿（2026-10-15 评审确立，为评审硬约束）
- 出处：`docs/plans/2026-10-15-综合修改计划评审结论.md`、`docs/plans/2026-10-18-004-Qoder优化开关与回滚说明.md`

## 背景

Qoder 对标整改与综合优化涉及大量行为与视觉变更（F1-F12、P1/P2 系列），一次性放开会造成不可回滚的体验断裂；评审中发现直接替换 60 处 alert/confirm 属于阻断级冲突。

## 决策

1. **一切新行为必须挂运行开关（runtimeFlags / 环境变量），默认关闭**。
2. 替换既有交互（如 alert/confirm → 自研弹窗）必须走 flag 门控 + 可回退，不允许无开关直接替换。
3. 回滚三层：**开关级**（关 flag 即回基线）、**单文件级**（git 还原单文件）、**整站级**（还原整批）。
4. flag 转正（默认开）是独立迭代：需真实任务验证 + 评审确认，不随功能开发顺带放开。

## 后果

- 正面：Qoder 对标十批优化可安全共存于主干；任何批次可独立回滚。
- 代价：代码内存在 opt-in 分支路径；需要维护 flag 清单与转正队列（12 项待转正）。
- 落点：`server/index.mjs` runtimeFlags 汇总；Qoder 视觉层由 `qoderStyle` 开关控制。

## 现状

- 已生效：全部 Qoder 优化与 PI-SDK 优化默认关；视觉/动效/交互改造均带门控与回退。
- 待办：flag 转正轮（见后续计划）；Modal 基座迁移并入转正轮。
