# BRD-007 桌面端路线收敛：Tauri 2 壳 + 本地优先

> **状态：已废弃（deprecated）**——壳技术决策被 [BRD-008-桌面端回归Electron架构](BRD-008-桌面端回归Electron架构.md) 取代（2026-10-19）。本文中「多用户三步走」「FEATURE_CLOUD 门控」「三层隔离」「Windows 优先」四项结论继续有效，已并入 BRD-008；Tauri 相关内容仅作历史记录保留。

- 状态：已定稿（2026-10-19，取代 BRD-002 中的 Electron 细节）
- 出处：`docs/plans/2026-10-19-多用户隔离与桌面端路线梳理.md`、`docs/plans/2026-10-19-上线部署项目实施计划.md`

## 背景

桌面端路线经历三次演变：Electron 优先（2026-08-21）→ 单主仓库双壳完整计划（2026-09-20，基线已过时）→ 上线部署与多用户隔离梳理（2026-10-19）。需要收敛最终路线。

## 决策

1. 桌面端采用 **Tauri 2 壳**：sidecar 方式直接复用现有 Express 服务端 + React 前端，不复制业务代码。
2. **本地优先**：officecli 随安装器分发；数据落本地工作区。
3. 云端能力由 `FEATURE_CLOUD` 开关统一门控，一套代码兼容本地/云端形态。
4. 多用户三步走：**内网/团队版先行 → 云 SaaS 多租户 → 混合**；"桌面端本身就是最强的隔离"——先补三层隔离（用户 → 工作区 → 运行时）。
5. Windows 优先。

## 后果

- 正面：壳体积小、复用度高；隔离与部署路径清晰。
- 代价：Electron 相关调研（2026-08-21 / 09-20 计划中的 IPC/主进程设计）废弃，仅保留"共享核心"原则（BRD-002）。
- 现状：内网多用户版 + Tauri 桌面端 POC 已完成收口（2026-10-19 实施计划 status: done）；下一步为三层隔离落地与 POC 验证扩展（见后续计划）。
