# 架构总览

> 本文是模块级架构文档，回答"系统如何组织、数据如何流动、边界在哪里"。产品定位与设计目标见 `DESIGN.md`，逐条决策依据见 `docs/decisions/`。基线 v0.11.55。

## 1. 进程模型

```
PowerShell 监督（scripts/ops/start-service.ps1，自动重启/退避/日志）
  └── node server/index.mjs（单进程，端口 3002）
        ├── Express 5 路由编排（index.mjs，≈207 个注册点）
        ├── Pi Agent SDK（进程内：createAgentSession / ModelRuntime / SessionManager）
        ├── builtin-browser 子进程（headless Edge/Chrome，CDP 控制）
        └── officecli 子进程调用（文档读写）
```

- 单进程承载全部业务，API Key 与文件权限不出服务端，浏览器只接触 REST/SSE。
- 监督进程负责崩溃重启与启动宽限（`STARTUP_GRACE_MS = 180_000`）。

## 2. 服务端模块边界（server/）

| 域 | 模块 | 职责 |
|---|---|---|
| 入口编排 | index.mjs | 路由注册、静态托管、运行开关（runtimeFlags）汇总 |
| Agent 会话 | agent.mjs · subagent-orchestrator.mjs | 会话生命周期、prompt/abort、子代理编排、工具注册、上下文注入（TaskEnvelope/记忆/KB 说明） |
| 安全策略 | approval-policy.mjs · command-safety-policy.mjs | 工具风险分级审批、高危命令拦截 |
| 事件流 | event-registry.mjs · event-protocol.mjs · event-normalization.mjs · event-storage.mjs · stream-connection.mjs | 115 种事件注册/校验、协议归一、持久化、连接预算与去重 |
| 运行产物 | runs.mjs · run-trace.mjs · run-budget.mjs · turn-budget.mjs · artifact-credibility.mjs · artifact-rollback.mjs | 运行记录、轨迹归约、双轨预算、产物归属与回滚 |
| 地图 GIS | map.mjs · map-visualization.mjs · map-analysis.mjs · map-report.mjs · map-template.mjs · layer-repository.mjs · spatial-analysis.mjs · traffic-sources.mjs · batch-export.mjs | 图层模型、可视化描述符、空间分析（等时圈/OD/网络分配）、报告与模板、批量导出 |
| Office | office.mjs · doc-engine.mjs · office-params.mjs · native-files.mjs | officecli 封装、文档渲染引擎、参数处理、原生文件流 |
| 知识库 | kb.mjs | kb.json 根目录配置、本地全文索引（加权打分）、图谱生成、IMA 云端代理 |
| 工作流 | workflow-registry.mjs · workflow-validation.mjs · workflows/ | 声明式领域工作流注册与依赖校验 |
| Pi 配置 | pi-runtime.mjs · pi-config.mjs · pi-network-proxy.mjs · provider-catalog.mjs · models-dev-catalog.mjs | SDK 运行时、凭据与网络代理、供应商目录、模型目录 |
| 联网与工具 | web-search.mjs · web-reader.mjs · builtin-browser.mjs · mcp-management.mjs | 检索/抽取/浏览器/MCP 接入 |
| 记忆 | memory-*.mjs | 分层记忆、memory_update 建议与确认 |
| 工作区 | workspace.mjs | 默认 `office-workspace/`，切换/校验/持久化 |

**边界规则**：

1. 业务模块不直接 `import` Pi SDK——统一经 agent.mjs / pi-runtime.mjs 适配层。
2. 所有 SSE 事件必须先在 event-registry 注册（名称/负载/语义），后端与前端的消费都以注册表为准。
3. 模块间相对导入；文件路径引用一律锚定模块自身位置（`path.resolve(__dirname, ...)`），不依赖 cwd。

## 3. 前端结构（client/src/）

```
App.jsx（模式分派：三栏办公 / 知识库全屏 / 模板库 / 设置）
├── 纯函数模块（19 个，可回归测试）
│   run-trace.js         运行轨迹归约（工具聚合/完成语义/token 统计）
│   run-display-projection.js  运行数据 → 展示态投影
│   stream-budget.js     SSE 流预算与去重（切工作区/会话防卡死）
│   event-display.js     事件 → 图标/文案/形态映射（toolIdentity）
│   layer-registry.js    地图图层注册表（归属/分组）
│   persist-ui.js        UI 状态持久化
│   theme.jsx            暗/亮主题
│   api.js               fetch 封装（控制面请求带超时与自愈）
│   file-urls.js         文件地址工具
│   …
└── components/（54 个）
    ChatPanel（对话流主面板：折叠/审批/结论卡/模型选择）
    DocViewer 系（DocxViewer/PptxViewer/ExcelGrid/MarkdownBody/CommentMarker）
    MapPanel 系（MapViewer/图层面板/属性表/测量/等时圈）
    TaskCenter / SubagentDetailPanel（任务与子代理）
    SessionSidebar / AgentMarket / WorkflowLauncher / SettingsPanel / ProviderLibrary
```

- 无全局状态库：组件内 state + 纯函数投影，数据流单向。
- SSE 事件按 event-registry 白名单消费，未知事件安全忽略。
- 展示逻辑优先落纯函数模块（对应 `scripts/*-test.mjs` 静态回归守护）。

## 4. 关键数据流

### 4.1 一轮对话的生命周期

```
用户输入 → POST /api/agent/prompt（含附件/当前文件注入）
  → agent.mjs 组装 TaskEnvelope（任务/工作区/记忆/KB 说明）
  → Pi session.prompt()
  → SDK 事件流 → event-normalization 归一 → event-registry 校验
  → SSE 推送（stream-connection 预算/去重）
  → 前端 run-trace 归约 → run-display-projection 投影 → ChatPanel 渲染
  → 工具调用（officecli/kb/map/browser…，高危走审批卡）
  → agent_end → run manifest 固化（轨迹/产物/预算）
  → 五要素固定总结（来源/修改/产物/假设/下一步）内嵌结论卡
```

### 4.2 中断链路

abort 请求 → 10 秒确认窗 → 服务端返回真实结果（runId + stillQueued 语义）→ 前端 agent_error 按中断处理，不残留错误文案。

### 4.3 地图编辑链路

Agent 调 map_edit → 服务端校验图层归属与审批 → layer-repository 落盘工作区 `maps/<项目>/layers/` → 可视化描述符 → 前端 MapViewer 渲染 → 界面与 Agent 视图实时一致。

## 5. 工作区与运行时目录模型

```
office-workspace/                 ← 默认工作区（server/workspace.mjs 硬编码，可切换）
├── 会话/运行记录/产物
├── maps/                         ← 地图项目
│   ├── <project>/layers/*.geojson|json
│   ├── <project>/style.json · map.config.json
│   └── settings.json
└── 用户文档与创作产物
kb.json（项目根）                  ← 知识库根目录配置（运行时配置）
```

- 工作区切换原子化（validate → switch），会话与产物随工作区隔离。
- 工作区数据为运行时数据，不入库（.gitignore）。

## 6. 测试与质量体系

- **测试即脚本**：`node scripts/*.mjs`，package.json 引用约 70 个 `test:*`。
- **CI**（.github/workflows/ci.yml，Node 22）：构建 + 16 个核心回归（事件注册表/任务结论/产物可信度/动效治理/对话流性能/流预算去重/地图系列/工作区隔离/供应商目录等）。
- `npm run verify`：语法 + 构建 + 40 项 API 冒烟，提交前必须通过（AGENT.MD 约束）。
- 事件注册表一致性、硬编码色值棘轮、无障碍配对校验均有专项测试。

## 7. 扩展点

| 扩展方向 | 落点 | 约束 |
|---|---|---|
| 新增 Agent 工具 | agent.mjs customTools | 先在 event-registry 注册事件；高风险工具须接审批策略 |
| 新增领域工作流 | workflows/ + workflow-registry | 声明式描述 + 技能依赖校验 |
| 新增模型供应商 | provider-catalog / models-dev-catalog | 区分目录/凭据/可调用三态 |
| 新增能力开关 | runtimeFlags（index.mjs 汇总） | 默认关闭，三层回滚（见 BRD-003） |
| 桌面端 | Electron 一体化：Node 侧即后端 + TS React 渲染层（BRD-009） | 分域绞杀迁移，功能等价验收；迁移期 legacy-http 仅本机绑定 |
