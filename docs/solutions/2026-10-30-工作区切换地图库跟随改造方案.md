# 工作区切换地图库跟随改造方案

## 背景与目标

现状：文档工作台工作区可切换（`setWorkspace` + `.workspace-state.json` 持久化恢复），但地图库 `MAPS_ROOT` 模块级常量锚定 `WORKSPACE_DIR/maps`（默认工作区），不跟随切换。目标：切换工作区后，地图项目、瓦片、样式、分析数据（bus-xinchang）全部解析到 `<当前工作区>/maps/`，实现「一个工作区 = 一套文档 + 一套地图库」的完整项目容器语义。

设计原则：
- 行为等价迁移：默认工作区下路径与现状完全一致（`PROJECT_DIR/office-workspace/maps`），全量回归可对拍
- 渲染面零改造：`oaw-data://maps/<项目>/...` URL 相对语义不编码盘符，roots 动态化后同一 URL 自动解析到新库
- 底图 Key（settings.local.json）保持全局（锚 PROJECT_DIR 不随工作区）——Key 是账号属性，不重复配置

## 改动设计

### 1. 单一事实源：mapsRoot 动态化

- `workspace.ts` 新增 `getMapsRoot(): string` = `path.join(getWorkspace(), "maps")`
- `map.ts`：`MAPS_ROOT` 常量 → `mapsRoot()` 函数（内部调 `getMapsRoot()`），9 处引用改调用；`MAP_SETTINGS_PATH/LOCAL_PATH` 改函数内拼（或设置读写函数内解析，保持全局锚 PROJECT_DIR——见决策）；`STATIC_ROOT` 同步函数化
- 决策：settings.json/settings.local.json（底图 Key）**保持全局锚 PROJECT_DIR**，不随工作区切换

### 2. 协议层：oaw-data roots 动态化

- `oaw-data-protocol.ts`：`OawDataRoots.maps` 类型扩展为 `string | () => string`，`resolveOawDataFile` 解析时求值（每请求生效）；index.ts 接线改传 `() => getMapsRoot()`
- 同步 `resolveOawDataFile` 纯函数测试

### 3. 切换钩子：失效与通知

- `workspace-direct.ts` `op:workspace:switch` 成功分支：广播 `workspace:maps-changed` 事件（event-registry 注册表新增，事件推送通道）
- renderer 地图面板监听该事件 → 重拉项目清单 + 重载当前 style
- `m3-xinchang.ts` / `traffic-sources.ts` bundled-xinchang：`DATA_DIR` 函数化跟随 `getMapsRoot()`

### 4. 子进程链：CLI 脚本参数化

- `scripts/tools/prepare-map-data.mjs`、`build-vector-tiles.mjs` 支持 `--maps-root=` 参数（或 `OAW_MAPS_ROOT` 环境变量）覆盖默认锚；默认锚保持 `PROJECT_DIR/office-workspace/maps`（CLI 直跑行为不变）
- runScript 调用点（electron/src/main/index.ts 打包态 runScript + agent-manager 地图工具链）传当前工作区 maps 路径
- `tiler.mjs`（`buildProjectTiles(MAP_DIR, ...)`）参数化无需改；`layer-repository.ts` 仅 import `LAYER_DEFS` 常量无需改

### 兼容性

- 新工作区无 `maps/` 子目录：`getMapsRoot()` 使用方懒创建（`mkdirSync recursive` 兜底），空库显示空项目列表
- migrate-legacy-data 保持固定锚（一次性迁移）
- `.trash`、`BUS_DATA_DIR`、项目清单扫描全部经 `mapsRoot()` 派生，无独立锚残留
