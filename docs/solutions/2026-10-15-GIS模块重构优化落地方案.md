# GIS 模块重构优化落地方案（对标高德问道/云睿能力体系）

- 日期：2026-10-15
- 依据：代码级走查（server/map.mjs 1334 行等 8 个服务端模块 + MapPanel/MapViewer/LayerPanel 前端三件套 + 38 个 /api/map/* 路由 + 7 个 map_* Agent 工具）+ 高德开放平台公开资料（2026-10 快照）
- 目标：按可商业化成熟交付的项目级标准，把 GIS 模块从"工作台内置能力"升级为**可独立交付的成熟功能模块**

---

## 0. 对标基线：高德"云睿·时空智能体平台"能力体系

高德 2026-08-18 发布云睿平台，采用 **MCP → Skill → Agent 三层递进**（官方比喻："MCP 是砖，Skill 是预制件，Agent 是精装房"）：

| 层 | 高德形态 | 内容 |
|---|---|---|
| MCP（砖） | 标准 MCP Server | 12 大核心高鲜度数据能力：地理编码/逆地理编码/IP 定位/天气查询/骑行·步行·驾车·公交路径规划/距离测量/关键词搜索/周边搜索/详情搜索 + 专属地图生成、一键导航、打车唤端 |
| Skill（预制件） | 行业方法论封装（如交通领域"高德问道"） | 把行业分析范式（区域交通流量分析、商圈诊断、业态分布分析、交通态势）封装为可被自然语言调用的能力模块，经标准化 Skill 市场开放 |
| Agent（精装房） | 开箱即用行业智能体 | 交通/文旅/产业/充电/商业五大行业智能体（如"高德问店"：商圈热力评估、业态扫描、租金坪效测算，输出结构化报告） |
| 数据底座 | 20+ 年时空数据 | 300+ 城市、700 万商家、2 亿+ POI；以 MCP 形态输出至阿里云百炼/千问办公等生态 |

**对标启示**：本项目的差异化定位是**交通规划领域的"问道式"能力**（OD 分析、等时圈、交通态势、路网结构）——恰好对应高德 Skill 层"行业方法论封装"的思路；缺口不在单点工具，而在**方法论封装层（Skill 化）与交付层（批量出图/报告）**。

## 1. 现状能力面（走查实证）

| 维度 | 已具备 | 缺失/不足 |
|---|---|---|
| 地图交互 | 缩放/指北/比例尺/点选查属性/测量线面/区域下钻/底图 5 档切换/globe/图层树（QGIS 风格：分组折叠/拖拽排序/符号缩略图/样式编辑/图例） | 无书签/视角收藏、无时间轴动画、无卷帘对比 |
| Agent 工具 | 7 工具（read/edit/import/datasets/analyze/save/clear），edit 支持 setVisibility/setPaint/move/add | 无"一步成图"类高层工具（如"对 X 做缓冲区分析并出图"需多步编排） |
| 空间分析 | heatmap/od/isochrone（demo + 真实适配器）、真实端点：等时圈/OSRM 路径/multi-isochrone/交通带宽/OD 期望线/交换桑基/路网结构 | **无缓冲区、无空间叠加（相交/裁剪/合并）、无栅格分析**；local-file 之外的 live-traffic-api/sql-database/gps-trajectory 适配器仅为占位未实现 |
| 自定义地图生成 | 项目 CRUD + style.json 组装 + 底图凭证注入 | 无"模板化地图"（预设配色/版式一键套用）、无一键专题图向导 |
| 图片导出 | 报告图导出 PNG（A4 横纵/方形/自定义、2-3x、标题/图例/比例尺/指北针合成）、即时截图 | **无 PDF、无批量导出（多项目/多图层组合/多尺寸）** |
| 数据底座 | 浙江 M2 数据、柬埔寨 OD、新昌公交、local-file（工作区 CSV/GeoJSON） | 无在线数据接入（高德/天地图 POI、实时路况）；适配器占位未实现 |
| 测试 | 4 个 test:map-* 套件（含 live 场景） | 无性能/大数据量回归基线 |

## 2. 重构优化方案（四层递进，对齐"砖→预制件→精装房"）

### 2.1 L1 数据与工具层（"砖"：补齐标准空间能力）

| 项 | 内容 | 技术选型 |
|---|---|---|
| G1 缓冲区/叠加分析 | map_analyze 新增 `buffer/intersect/union/clip` 分析类型；纯 JS 实现 turf.js 等价子集（零新增依赖，复用现有 geojson-vt 技术栈风格手写几何算法）或经数据管道脚本预处理 | 服务端几何算法模块（新增 server/空间分析.mjs），map_analyze 扩展 analysis 枚举 |
| G2 数据适配器落地 | 实现 live-traffic-api（HTTP 轮询可配置端点）与 sql-database（better-sqlite3 读本地库）两个占位适配器；统一 `registerSource` 契约不变 | 交通数据源.mjs 扩展，遵循既有适配器描述符协议 |
| G3 地理编码/POI 搜索接入 | 以 **MCP 桥**接入高德 MCP Server（项目已有 mcp管理.mjs 基础设施，Streamable HTTP 接入 `https://mcp.amap.com/mcp?key=...`），Agent 获得 geocode/POI/路径规划能力，结果可直接转地图图层 | 复用 mcp管理.mjs，零核心改动；key 由用户配置 |
| G4 在线底图安全化 | 现有高德 3 档底图凭证注入审计 + key 配额提示 | map.mjs hydrateBasemapSources 增强 |

### 2.2 L2 方法论层（"预制件"：Skill 化，本项目核心差异化）

| 项 | 内容 | 说明 |
|---|---|---|
| G5 **场景化分析模板（Skill 化）** | 把高频规划范式封装为一键模板：① OD 通勤分析（数据导入→期望线→带宽分级→结论要点）；② 设施可达性（等时圈×N→覆盖率矩阵→短板区清单）；③ 路网结构诊断（路网结构→瓶颈段→改造建议）。每个模板 = 确定性编排（复用编辑流水线 Planner→Writer→Evaluator 范式）+ 产物（图 + 表 + Markdown 结论） | 对齐"高德问道"思路：**行业方法论封装为可自然语言调用模块**；实现载体复用 P2-A 编辑流水线基础设施，新增 server/地图模板.mjs |
| G6 一键专题图向导 | 数据选入→配色方案（预设 5 套规划常用色板）→图例/标题/比例尺模板→出图 | 前端向导弹窗 + style.json 模板化写入 |

### 2.3 L3 交付层（商业化硬指标）

| 项 | 内容 | 说明 |
|---|---|---|
| G7 **GIS 图片批量导出** | 批量导出队列：多项目 × 多图层组合 × 多尺寸（A4/A3/自定义）× 多格式（PNG/PDF），后台任务化（复用 U5 内核侧车思想：导出任务独立执行不阻塞 UI），产物进成果管理 | 扩展现有报告图导出（MapPanel.jsx:757-890）为服务端可编排任务；PDF 用 Page.printToPDF 思路（canvas→PDF 零依赖手写或 jszip 内嵌 SVG） |
| G8 分析报告一键成文 | 分析结论 + 图集 + 数据表 → Markdown/Word 报告（复用原生文档引擎 docx 直写） | 与编辑流水线共用 Formatter |
| G9 交付物打包 | 项目（style.json + layers + tiles 索引 + 报告）一键打包 zip 归档，跨环境可恢复 | jszip 已有 |

### 2.4 L4 体验层

| 项 | 内容 |
|---|---|
| G10 视图书签与卷帘对比 | 视角收藏（center/zoom/bearing 一键恢复）、双图层卷帘（swipe）对比 |
| G11 时间轴动画 | 时段数据（流量/OD）按时间轴播放（M2 数据已有时段维度） |
| G12 性能基线 | 大图层（≥5 万要素）帧率与内存回归脚本，纳入 CI |

## 3. 迭代路径与验收标准

| 阶段 | 内容 | 交付物 | 验收标准 |
|---|---|---|---|
| 第一阶段（P0） | G1 缓冲/叠加 + G7 批量导出 + G8 报告成文 | 空间分析.mjs + 批量导出任务 + docx 报告 | 缓冲区分析对 1 万要素 ≤2s；批量导出 3 项目×3 尺寸队列完成且产物进成果管理；报告含图/表/结论三要素 |
| 第二阶段（P1） | G5 三大场景模板 + G6 专题图向导 | 3 个 Skill 模板 + 向导 UI | 模板端到端：自然语言触发→自动编排→产物落盘；向导 5 步内完成一张专题图 |
| 第三阶段（P1） | G2 适配器落地 + G3 高德 MCP 桥 | 2 个数据适配器 + MCP 接入配置 | 外部 CSV/SQLite 数据出图；geocode 结果一键转图层 |
| 第四阶段（P2） | G9/G10/G11/G12 | 打包归档/书签卷帘/时间轴/性能基线 | 项目 zip 跨环境恢复可用；5 万要素帧率 ≥30fps |

## 4. 成熟度评估结论

当前 GIS 模块交互底座（图层树/测量/导出/Agent 工具）已达工作台级良好水平；距离"可独立交付"的差距集中在：**① 分析深度（缓冲/叠加缺失）、② 方法论封装（无 Skill 化模板，用户需自行多步编排）、③ 交付闭环（无批量/PDF/报告成文）、④ 外部数据接入（适配器占位）**。按本方案 L1→L3 优先序补齐后，可形成"交通规划领域问道式能力"的差异化定位——与高德体系错位竞争（高德强在鲜度数据与 POI 底座，本项目强在**规划方法论编排与本地数据分析**）。
