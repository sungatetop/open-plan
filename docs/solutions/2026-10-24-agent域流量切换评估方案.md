# agent 域流量切换评估方案

> B2-17 收官（装配层过渡桥清零、legacyTools 45 成员全 TS 直绑）后的下一个主线批是
> "TS AgentManager 承载流量"。本方案为该批的**评估侦察产出**（纯只读，未改任何行为），
> 回答四个问题：门控逻辑现状是什么、旧路径消费面有多大、TS 侧行为面等价证据与缺口在哪、
> 切换该怎么分步与回滚。

## 1. 门控逻辑现状（侦察①）

现状（[main/index.ts](file:///d:/open-plan/electron/src/main/index.ts)）：

- `OP_DESKTOP_AGENT_DOMAIN`（L149）默认关；**无论开关，legacy sidecar 都启动**
  （bootstrap L189 `startLegacyServer`）并承载全部业务流量。
- flag=1 的全部行为差异仅有两点：
  1. SMOKE+legacy-client 形态：ready 后先装配 TS AgentManager，成功才输出 `SMOKE_OK`（L198）；
  2. 非 SMOKE：ready 后 `assembleAgentDomainInBackground()` 后台构造单飞实例（L203）。
- **TS AgentManager 装配后不承载任何流量**：没有进程内调用方，没有 HTTP 服务化，
  渲染层（无论 legacy-client 还是 app 形态）的请求全部仍走 sidecar。

**关键结论：当前 flag 的语义只是"装配自检"，不是流量开关。翻 flag 默认值 ≠ 流量切换**
——翻默认值只会让每次启动多构造一个闲置的 AgentManager 实例（与 sidecar 旧实例并发，
runs/memory 文件族虽跨实例互斥，但闲置实例徒增风险面而无收益）。真正缺的是**流量承载路径**。

## 2. 旧路径消费面盘点（侦察②）

### 2.1 两个 renderer 形态，两条完全不同的通道

| 形态 | 入口 | 业务通道 | 事件通道 |
|---|---|---|---|
| legacy-client（`OP_DESKTOP_NEW_UI` 默认关，现行生产形态） | 加载 sidecar 提供的 `http://127.0.0.1:port/`，旧 client 全业务 **HTTP/SSE 直连 sidecar** | sidecar 258 条路由 | 3 条 SSE：`/api/agent/stream`、`/api/agent/events`、`/api/memory/stream` |
| app（flag=1，新 UI） | IPC invoke → main 转发器 → sidecar HTTP | [channels.ts](file:///d:/open-plan/electron/src/shared/protocol/channels.ts) 91 条通道映射 sidecar 路由 | main 侧三个 SSE 桥（events/global-events/memory-events-bridge）消费 sidecar SSE → `op:event` 推送 |

### 2.2 sidecar 258 条路由的域划分（对切换面的意义）

- **agent 域承载面**：`/api/agent/*`、`/api/sessions*`、`/api/runs*`、`/api/artifacts*`、
  `/api/memory/*`、模型/配置族——路由处理内联在 [server/index.mjs](file:///d:/open-plan/server/index.mjs)，
  直接调 agentManager（全文件 51 处调用点）。
- **非 agent 域**（office/doc、map、kb、templates、files、projects、workspaces、file-roots、
  search/map settings、system）：独立模块实现，与 AgentManager 无关，**不在切换面内**，
  长期继续由 sidecar 承载直至 B6 逐域收编。

### 2.3 invoke 通道按 AgentManager 依赖分层（91 条中约 59 条在切换面内）

| 层 | 通道族 | 特征 |
|---|---|---|
| A 层（live 态强依赖，编排厚） | `op:agent:prompt/abort/answer/approval/new/resume/compact/session-tree/session-branch` + 会话族 10 条 + 运行族 14 条 | 路由编排内联在 index.mjs（admission 信封组装、run 创建/入队/recover、session-store 路由逻辑），**尚未迁 TS** |
| B 层（方法直映射，编排薄） | `op:agent:model:set/runtime/pending/approvals/approval(-mode)/stream-close/events-state/events-read` | 基本一行映射 agentManager 方法 |
| C 层（配置族，读文件为主） | auth/custom-provider/config-status/import/plans/model-configs/provider-catalog/default-model/probe/diagnostics/permissions/network-settings + `op:models:*` + memory proposals 族 | 依赖 listModelCatalog/refreshModels/probeModel 等无 live 态方法 |
| D 层（事件面） | 3 条 SSE 桥 | 对话流事件源切换是切换批的**前置件**（见 §3 缺口 2） |

## 3. 行为面等价证据与缺口（侦察③）

### 3.1 已有证据（模块级/实例级对拍，全绿）

- agent-manager 本体：B6 系列 15 个对拍（create/thin/context/prompt-chain/queue/model/
  lifecycle/emit/io/pure/subagent/create-tools/pi-runtime/pi-config/pi-network/approval/
  workspace-write-coordination）。
- 工具域：B2 系列 17 个域对拍（runs/memory/memory-admission/office-params/file-permission-error/
  workspace-guard/project-management/kernel-sidecar/map-analysis/editorial-pipeline/mcp/
  web-search/web-reader/builtin-browser/pi-extension/doc-engine）。
- 装配层：`b2-agent-assembly` 7 用例 + 装配冒烟 `AGENT_DOMAIN_ASSEMBLED`。
- 协议对账：`channels-manifest`（91 通道 ↔ server 路由面无幽灵/缺漏）、`event-registry-parity`。

### 3.2 缺口清单（切换前必须补齐）

1. **HTTP 编排层未迁 TS**（最大缺口）：index.mjs 内联的 A 层编排——prompt admission
   响应组装（PromptAdmissionResponse 13 字段）、run 创建/入队/恢复（recover/continuation）、
   会话族路由逻辑（session-store 状态机）、事件游标状态机——约对应 index.mjs 数千行。
   B6/B2 对拍只覆盖 AgentManager 方法面，不覆盖"路由 → AgentManager"编排面。
2. **进程内事件管道缺失**：TS AgentManager 的 emitDeps 已绑 runs 域 recordRunEvent
   （事件**落盘**侧等价），但事件从 TS 实例到渲染层的**推送**管道不存在——旧路径靠
   sidecar SSE 桥，TS 实例不在 sidecar 里，SSE 连不上它。需要 TS emit → `op:event`
   进程内直推（替代对话流 SSE 桥），且 seq/id 语义须对齐 event-registry 契约。
3. **legacy-client 不可切**：旧 client 全业务直连 sidecar，其 agent 域无法受益于
   进程内直调。切换只能作用于 app 形态；sidecar agent 域必须与 TS 实例**共存**
   直到旧 client 退役（F 线收尾）。
4. **双实例并发**：切换后 sidecar 旧 agentManager（服务 legacy-client）与 TS 实例并存。
   runs/memory 文件族锁互斥 B2-4 已验证；sessions 文件与事件游标的跨实例并发
   需在切换批验证（同一 workspace 双形态混用是边缘场景，方案上显式声明或加文件锁）。

## 4. 分步切换方案（草案 S1-S4）

原则：绞杀者模式逐通道族推进，每批一个域、flag 默认关、跨实例共存、随时可翻回。

| 步骤 | 内容 | 验收 |
|---|---|---|
| S1 事件直推管道 | TS AgentManager emit → main `op:event` 进程内直推（flag 控制，默认关）；app 形态对话流事件源可切直推，sidecar SSE 桥保留为回退 | 事件对拍 + app 形态冒烟对话流事件序列与旧路径一致 |
| S2 B 层直调 | B 层 10 条通道从"转发 sidecar"改为进程内调 TS AgentManager（薄映射先行，风险最低）；per-域 flag 默认关 | 通道级对账测试 + 单跑对拍全绿 + 门禁四项 |
| S3 A 层编排转录 | index.mjs A 层编排转录为 TS 路由器（量大，拆 2-3 批：会话族 → 运行族 → prompt/abort/answer/approval 主链） | 每批跨仓对拍（编排层行为面）+ app 形态真实 prompt 冒烟（内网供应商） |
| S4 默认路径翻转 | C 层配置族直调收尾后，翻转 app 形态默认路径（flag 默认开或摘除转发分支）；legacy-client 与 sidecar agent 域退役顺序与 F 线联动决策 | 全量回归 + SMOKE_OK + 供应商联调冒烟 |

回滚：每步独立 flag，翻回即走 sidecar 旧路径（sidecar 始终在运行），回滚零成本。

## 5. 风险清单

| # | 风险 | 缓解 |
|---|---|---|
| 1 | A 层编排未迁，S3 工作量与行为回归风险最大 | 逐批对拍转录 + 真实冒烟；编排层纯函数部分可先行单测 |
| 2 | 双实例并发写 sessions/事件游标 | 复用 B2-4 文件锁体系；切换批补跨实例并发测试；文档声明不混用 |
| 3 | seq/id 语义：SSE 全局游标 vs 直推的通道内序号 | S1 先做 event-registry 契约对齐与对拍 |
| 4 | prompt admission 超时语义：HTTP 转发 120s 超时 vs IPC invoke 无超时 | S3 显式对齐（admission 快速返回，长任务走事件流，语义天然兼容） |
| 5 | legacy-client 长期共存造成双路径维护成本 | F 线旧 client 退役节奏与 S4 联动，避免无限期共存 |

## 6. 决策点（本方案停下来等确认的原因）

1. **是否按 S1→S4 顺序推进**，还是调整优先级（如先 S3 主链后 S1）？
2. **S2 起步粒度**：B 层薄映射先行（推荐，风险最低）还是直接从 prompt 主链开切？
3. **双实例共存声明**：接受"同一 workspace 不双形态混用 agent 会话"的显式约束，
   还是要求补齐跨实例会话文件锁后再切？
4. 翻默认值（`OP_DESKTOP_AGENT_DOMAIN` 默认开）**不在本批**——它只是装配自检开关，
   建议维持默认关直至 S4；是否同意。
