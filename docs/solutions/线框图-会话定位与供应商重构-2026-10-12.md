## 一、会话定位导航（图一 → 图二 式）

### 现状（已核实代码）

`client/src/components/ChatTimeline.jsx` 目前已经有：右侧细横杠时间线（bead）、滚动位置高亮（active）、**点击跳转**（`onClick → scrollToMsg`）、悬停小提示（`bead-tip`，只有单行摘要 + 角色字母）、重复消息合并（`count`）。

问题不在"能不能跳"，而在**看不见**：横杠只有 2px 宽、提示是单行小气泡、没有上下文列表，所以"像图二那样一眼看到几条消息、点哪跳哪"的体验缺失；你截图里的红框区域正是这条 rail 撑出来的空白列。

### 方案 A：悬停弹层（保留 rail，加富信息层）——推荐

```
                    对话区                          rail（保留）        悬停时弹层（新增）
 ┌──────────────────────────────────────────┐   ┌──┐   ┌───────────────────────────────┐
 │ 我要求是我输入之后立马就可以显示思考…        │   │▬▬│◄──│ ▸ 我：输入后立马显示思考…       │
 │                                          │   │▬▬│   │   10:12 · 3 条合并            │
 │ 收到——「输入后立刻显示思考」我一起做掉…      │   │██│◄──│ ▸ 助手：收到——「输入后立刻…    │ ← 当前项
 │                                          │   │▬▬│   │   10:12                       │   高亮边框
 │ 查一下 pi 里内置多少供应商…                 │   │▬▬│   │ ▸ 我：查一下 pi 里内置多少…    │
 │                                          │   │▬▬│   │   10:20                       │
 │                                          │   └──┘   │ ▸ 助手：33 个内置供应商…      │
 │                                          │          │   10:24 · 含 Key 状态         │
 │                                          │          └───────────────────────────────┘
 └──────────────────────────────────────────┘
   悬停 rail 上的任意横杠：弹层列出该位置前后 ~10 条（角色 + 两行摘要 + 时间 + 合并数）
   点击条目 = 跳转；↑/↓ 移动高亮、Enter 跳转；Esc 关闭；底部固定「顶部 / 底部」两个快捷跳转
```

要点：
- 弹层位置跟随 rail 垂直居中，**不遮挡对话正文**（右外侧 12px，宽度 260–300px）；
- 当前阅读项高亮（图二里那个带边框的卡片就是"当前项"）；
- 角色用 U/A 小徽标区分（与现有 `bead-tip` 一致，不用新图标）；
- 键盘可达（`role="listbox"` + `aria-activedescendant`），窄屏降级为点击打开、全屏底部抽屉。

### 方案 B：合并成一个"导航列表"（rail 只当把手）

```
 ┌──────────────────────────────────────────┐   ┌──┐
 │ 对话区                                    │   │▬▬│  ← rail 变成"把手"（不再承担定位）

 │                                          │   │▬▬│
 └──────────────────────────────────────────┘   └──┘
                          ┌─────────────────────────────────────────────┐
                          │ 会话导航            24 条 · 当前第 9 条      │
                          │ ─────────────────────────────────────────── │
                          │ ▸ 我：输入后立马显示思考…          10:12    │
                          │ ▸ 助手：收到——「输入后立刻…        10:12 ✓  │ ← 当前
                          │ ▸ 我：查一下 pi 里内置多少供应商…   10:20    │
                          │ ▸ 助手：33 个内置供应商，可以导入…  10:24    │
                          │ ▸ 我：这个图一是现状的…             10:31    │

                          └─────────────────────────────────────────────┘
```

A 与 B 的差别：A 是"轻量悬停预览"（不打断、适合快速定位）；B 是"完整导航面板"（适合长会话跳远，能看全貌、带搜索/过滤）。**建议：A 为主 + B 作为"展开"入口**（弹层右上角一个"展开全部"图标切到 B 的面板），一套组件两种密度。

## 二、自定义供应商 / 网络 面板重构（图三）

### 现状问题（对照截图）

- 三个标签页混在一起：`模型套餐`、`自定义供应商`、`网络` —— 但"供应商"和"网络"其实是一件事的两半（谁提供模型 / 怎么连出去），放在同一页容易互相干扰；
- 供应商行信息过载且缺关键动作：`command-code · command-code · OpenAI Chat Completions · 63 个模型`，右侧只有 `启用 / Key 已配置 / 编辑 / 删除` —— **没有"测试连接""看模型清单""设为默认"**；
- 只能"新增供应商"（手填 Base URL / API 类型 / 模型），**没有"从 Pi 内置供应商一键添加"**（见第三节）；
- `new-provider` 这种空壳行与真实供应商并列，缺少状态分层（未配置 / 已配置未启用 / 正常）；
- 网络（代理）设置独立一页，但连不通时用户会先怀疑供应商，**缺少把两者串起来的诊断入口**。

关键改动：
1. **拆页**：`模型供应商` 与 `网络与代理` 各占一页（原"自定义供应商/网络"合页）；
2. **我的供应商**：行内加 `测试连接`、`设为默认`、`⋯`（重命名/复制/删除）；状态徽标统一为 `●已连通 / ○未配置 / ⚠认证失败`；
3. **Pi 内置供应商库**：可搜索、显示 env 变量名与模型数，`＋添加` 一步导入（Base URL/协议/模型目录自动带出，只需补 Key）；
4. **连接诊断**：把"供应商连不通"和"代理没配好"串成一个体检流程，结果落成时间线；
5. 顶部卡片（Agent 模型 / 外观 / 当前项目）保持不变，作为"一眼看状态"的入口。

## 三、Pi 内置供应商：能否直接拿来？

### 调查结论（已核实）

**能，而且数据已经在本机。**

- Pi（`@earendil-works/pi-coding-agent`）的 SDK 里内置了完整供应商注册表：**33 个 API-Key 供应商**（含 `ANT_LING / NVIDIA / GEMINI / GROQ / CEREBRAS / XAI / FIREWORKS / TOGETHER / BASETEN / OPENROUTER / AI_GATEWAY / ZAI_CODING_CN / MISTRAL / MINIMAX(_CN) / MOONSHOT / OPENCODE / KIMI / META / CLOUDFLARE / QWEN_TOKEN_PLAN(_CN) / XIAOMI(_API / TOKEN_PLAN_CN/AMS/SGP) / GOOGLE_CLOUD / RADIUS / TYPESAFE / LLAMA …`），另有 OAuth 类（如 GitHub Copilot、openai-codex）与云凭证类（Bedrock / Vertex）。
- 每个供应商都带 **Base URL**（实测 43 个内置 baseUrl，例如 `https://api.ant-ling.com/v1`、`https://api.anthropic.com`、`https://api.cerebras.ai/v1`）、**API 协议类型**（openai-completions / anthropic-messages / openai-responses / google-vertex …）与**模型目录**（内置模型 id 200+，如 claude-*/gpt-*/o3/…）。
- 定义位置：`node_modules/@earendil-works/pi-coding-agent/dist/bundle/chunks/chunk-OIM2DMFI.js`（供应商清单 + env 变量表）；SDK 同时导出 `ModelRegistry`、`ModelRuntime`、`composeModelProvider`、`ModelConfig`，可由服务端**直接枚举**（不必解析 bundle 文件）。
- 本应用目前只露出 **9 个**（command-code 63 / opencode-go 31 / anthropic 17 / openai-codex 11 / command-code-anthropic 8 / xiaomi-token-plan-cn 4 / minimax 3 / minimax-cn 3 / deepseek 2 = 142 个模型）——因为 `/api/models` 只列**已配置/有凭据**的供应商。其余 24 个内置供应商在 UI 里完全不可见，只能手填 Base URL 新增。

### 图标方案（你问的"增加各个供应商的图标"）

- Pi **不自带**供应商 logo（`docs/images` 里只有 4 张界面截图），所以要自己做：
  - **推荐**：内置一套内联 SVG 品牌标记（约 20 个主流：Anthropic、OpenAI、Google、DeepSeek、xAI、Groq、Mistral、Cerebras、NVIDIA、Together、Fireworks、OpenRouter、Moonshot/Kimi、MiniMax、Qwen、Xiaomi、Meta、Cloudflare、Azure、Vercel），来源用 simple-icons 的路径数据（CC0），**不引入运行时依赖**；
  - 其余供应商走**首字母色块兜底**（现有 `providerInitials` 已实现，按 provider 名生成稳定色相）；
  - 商标只用于"标识对应供应商"，不加任何暗示合作/背书的文案（如需要更保守，可全部改用首字母色块，把品牌图标做成可选设置项）。
