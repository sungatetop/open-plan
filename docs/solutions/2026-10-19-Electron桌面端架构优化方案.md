# Electron 桌面端架构优化方案

> **状态：已被取代**——sidecar 复用 + JS 前端路线升级为 [2026-10-19-Electron一体化TypeScript重构方案](2026-10-19-Electron一体化TypeScript重构方案.md)（BRD-009）。本文 §1 选型论证、§4.5 安全边界、§4.4 WebContentsView 设计继续有效并已并入新方案；sidecar 进程形态与"复用 JS 前端"策略不再采用。以下内容仅作历史记录。

> 决策依据：[BRD-008-桌面端回归Electron架构](../decisions/BRD-008-桌面端回归Electron架构.md)（取代 BRD-007 Tauri 路线）。本文为可实施的详细设计。基线 v0.11.55。

## 1. 背景与选型论证

### 1.1 为什么从 Tauri 回到 Electron

| 维度 | Tauri 2 | Electron | 结论 |
|---|---|---|---|
| 内置浏览器 | 系统 WebView2 承载，多视图/CDP 控制弱 | `WebContentsView` 原生多视图 + 完整 Chromium 控制面 | **Electron 质变**：地图/报告预览需要真实浏览器表面（标签/下载/权限/焦点/选择），2026-09-20 计划已论证截图流不可持续 |
| 技术栈同构 | Rust 壳 + Node sidecar，异构工具链 | 主进程即 Node，`spawn` 现有 server 零改造 | **Electron 同栈**：服务端 Express 5 直接复用 |
| 历史资产 | POC 资产作废 | 2026-08-21 / 2026-09-20 两份计划的预加载桥、版本化 IPC、Runtime Adapter、权限策略设计直接复活 | **Electron 资产复用** |
| 打包分发 | 体积小（~10MB 壳） | ~150MB 级 | Tauri 占优，但单机工作台场景可接受 |
| 自动更新 | tauri-updater | electron-updater（NSIS 差分更新成熟） | Electron 略优 |
| 安全补丁 | 跟随系统 WebView2 | 需自管 Chromium 升级节奏 | Tauri 占优，纳入风险对策（§6） |

综合：**内置浏览器是产品刚需（地图与报告预览主场景），同栈与资产复用显著降低实施风险**，体积与补丁代价可接受。

### 1.2 沿用的既有结论（不因换壳改变）

- 单主仓库共享核心，不复制业务代码（BRD-002 原则）。
- `FEATURE_CLOUD` 门控一套代码兼容本地/云端（BRD-007 继承）。
- 多用户三步走：内网先行 → SaaS → 混合；先补三层隔离（用户 → 工作区 → 运行时）。
- Windows 优先；一切新行为挂 flag 默认关（BRD-003）。

## 2. 总体架构

```
┌─────────────────────────── Electron 应用 ───────────────────────────┐
│                                                                     │
│  主进程 electron/main/（Node）                                       │
│  ├─ app 生命周期：单实例锁、窗口托管、托盘、协议注册、崩溃上报        │
│  ├─ sidecar 管理器：spawn "node server/index.mjs"（:3002）           │
│  │    健康检查 /api/status → 崩溃指数退避重启 → 优雅退出(SIGTERM)     │
│  ├─ IPC 路由：版本化能力协议（desktop.v1）                            │
│  ├─ WebContentsView 托管器：内置浏览器原生承载（替代 CDP 截图流）      │
│  └─ 安全策略：contextIsolation、CSP、文件/外壳访问白名单              │
│            ↕ contextBridge（preload，最小暴露面）                    │
│  渲染进程 = 现有 React 应用（client/ 构建产物，不复制不改造）          │
│  ├─ 三栏工作台 / 知识库 / 地图 / 任务中心 …… 与网页端完全一致          │
│  ├─ 业务协议不变：REST + SSE（event-registry 115 种事件两端共享）      │
│  └─ 平台差异经 window.opDesktop（desktop.v1）探测与调用               │
│            ↕ HTTP/SSE (127.0.0.1:3002)                              │
│  sidecar：现有 server/index.mjs（Express 5 + Pi SDK，不改架构）       │
└─────────────────────────────────────────────────────────────────────┘
```

核心原则：**桌面端 = 网页端 + 平台壳**。业务逻辑零复制；平台能力（窗口/浏览器/文件/更新）走 IPC；差异在运行时探测，同一套前端代码两种形态可用。

## 3. 目录与代码组织（新增 electron/）

```
electron/
├── main/
│   ├── index.mjs          主进程入口（app 生命周期/单实例/窗口/托盘）
│   ├── sidecar.mjs        服务子进程管理（spawn/健康检查/退避重启/优雅退出）
│   ├── ipc-router.mjs     版本化 IPC 路由（desktop.v1 能力分发）
│   ├── browser-host.mjs   WebContentsView 托管器（创建/布局/焦点/销毁）
│   ├── updater.mjs        electron-updater 封装（检查/下载/安装提示）
│   └── security.mjs       CSP、导航白名单、外部链接拦截
├── preload/
│   └── index.cjs          contextBridge：仅暴露 window.opDesktop
└── renderer-bridge/
    └── desktop-capability.js   前端侧平台探测与降级封装（引入 client/src）
package.json(electron)     electron-builder 配置（或根 package.json 扩展）
```

- `client/`、`server/` **零改动**是硬约束；桌面专属逻辑只进 `electron/` 与一个前端桥接模块。
- 前端桥接模块（`desktop-capability.js`）提供 `isDesktop` / `invoke(channel, payload)`，全部调用点带降级：网页端调用返回 `unsupported`。

## 4. 关键设计

### 4.1 进程模型与生命周期（sidecar.mjs）

1. **启动**：app ready → 单实例锁（`app.requestSingleInstanceLock`）→ spawn sidecar（`process.execPath` 复用 Electron 内置 Node 或捆绑 Node 运行时，`ELECTRON_RUN_AS_NODE=1`）→ 轮询 `/api/status` 就绪 → 创建主窗口。
2. **健康守护**：每 5s 探活；连续失败按指数退避重启（1s/2s/4s/…上限 30s），连续 5 次失败弹错误窗（日志路径 + 重启按钮）。
3. **优雅退出**：window-all-closed 或托盘退出 → 向 sidecar 发 SIGTERM → 15s 未退 SIGKILL → app quit。运行中 Agent 任务通过 `/api/status` 忙碌态阻止误退（弹确认）。
4. **端口策略**：3002 被占用时由主进程在 3002-3099 间选空闲端口，通过环境变量 `PORT` 传给 sidecar，前端经 IPC 获知实际端口。
5. **日志**：sidecar stdout/stderr 重定向至 `%APPDATA%/guiju/logs/sidecar-YYYYMMDD.log`，滚动保留 7 天。

### 4.2 渲染层复用与双形态

- 生产：主窗口 `loadURL(http://127.0.0.1:<port>)`——与网页端同一服务地址，SSE/REST 链路完全一致。
- 开发：`npm run dev:desktop` 顺序启动 Vite(5173) + server(3002) + Electron（加载 5173，HMR 可用）。
- 形态探测：`window.opDesktop` 存在即桌面端；网页端功能不受影响（同一构建产物）。
- 菜单/标题栏：默认隐藏系统菜单，自绘标题栏（`titleBarStyle: hidden` + CSS `--op-titlebar`），与现有顶栏设计融合。

### 4.3 预加载桥与版本化 IPC（desktop.v1）

```js
// preload/index.cjs —— 唯一暴露面
contextBridge.exposeInMainWorld("opDesktop", {
  version: "1",                                  // 协议版本，前端可协商
  capabilities: ["window", "browser", "fs.dialog", "shell.open", "update", "power"],
  window:    { minimize, maximize, close, onStateChange },
  browser:   { open, navigate, back, forward, onViewportReady, onAgentEvent },
  fs:        { pickDirectory, pickFile, revealInExplorer },
  shell:     { openExternal },
  update:    { check, onProgress, install },
  power:     { keepAwake }                        // 长任务防休眠
});
```

- **版本协商**：前端校验 `version === "1"`，不匹配则按网页端形态运行（能力降级不报错）。
- **能力面收敛**：IPC 只暴露上表动作，不接受任意通道字符串；每个 handler 在主进程白名单注册（ipc-router.mjs）。
- 与 2026-09-20 计划的关系：该计划的"版本化 IPC + 能力协议"思想落地于此；**阶段 1 不做全量能力协议**——业务仍走 HTTP/SSE，仅平台能力走 IPC（风险最小的增量路径）。

### 4.4 内置浏览器升级（browser-host.mjs）——本次优化的核心

现状（网页端）：`server/builtin-browser.mjs` 启动 headless Edge/Chrome 经 CDP 截图流 + 坐标转发——观察通道可用，人工浏览体验差（漂移/焦点/下载/权限缺失）。

桌面端方案：

1. **承载**：`WebContentsView` 叠加在主窗口内容区（与 React 布局联动，拖拽分栏时同步 setBounds），真实页面表面，原生焦点/选择/滚轮。
2. **双通道共存**：
   - 网页端：保留 CDP 截图流通道（`server/builtin-browser.mjs` 不动）；
   - 桌面端：Agent 浏览器工具事件经 sidecar → IPC `browser.onAgentEvent` 驱动同一 WebContentsView——Agent 与人操作同一视图，互相可见。
3. **操作队列**：延续既有"用户操作与 Agent 操作代际/所有权管理"设计（09-20 计划 §2.3 的队列方案落地）：Agent 导航前经审批卡确认（approval-policy 已有分级），用户操作即时抢占并标记代际。
4. **下载与权限**：`session.setDownloadLocation`（默认工作区 `downloads/`）+ `setPermissionRequestHandler` 白名单（摄像头/麦克风默认拒绝，通知拒绝）。
5. **降级链**：WebContentsView 异常 → 自动回退 CDP 截图流模式（flag：`desktopBrowserNative`，默认关，转正轮开启）。

### 4.5 安全边界（security.mjs）

| 面 | 策略 |
|---|---|
| 渲染进程隔离 | `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`（preload 除外） |
| CSP | `default-src 'self' 127.0.0.1:<port>`；禁 `unsafe-eval`（Vite 构建产物满足）；地图瓦片域名白名单 |
| 导航 | `will-navigate` 白名单（仅本机服务地址）；外部链接 `shell.openExternal` 托管 |
| 凭据 | API Key 仅存 sidecar 进程（Pi 配置目录），渲染进程永不可见（与网页端同保障） |
| 文件系统 | IPC `fs.*` 仅系统对话框选目录/文件与 revealInExplorer，不提供任意路径读写 |
| 审批 | 高危命令继续走服务端 command-safety-policy + 审批卡，桌面端不新增旁路 |

### 4.6 打包与分发（electron-builder）

1. **构建**：`npm run dist:win` → NSIS 安装包（`Guiju-Setup-<ver>.exe`）+ 便携版 zip。
2. **捆绑**：client/dist（React 构建产物）+ server/ 源码 + Node 运行时（Electron `ELECTRON_RUN_AS_NODE` 或独立 node.exe）+ officecli 二进制。
3. **排除**：node_modules 按依赖图裁剪（devDependencies 剔除）；`docs/`、`scripts/`、数据归档不入包。
4. **自动更新**：electron-updater + 内网更新源（静态文件服务器或 GitHub Releases）；更新前检查 sidecar 空闲态，繁忙则提示。
5. **首启体验**：首启向导（选工作区目录 → 模型凭据配置引导 → 完成）；工作区默认 `%USERPROFILE%/GuijuWorkspace`，可迁移现有 office-workspace。

### 4.7 数据与目录模型

- `%APPDATA%/guiju/`：logs/、updater/、窗口状态。
- 工作区（会话/产物/maps）默认用户目录、可配置——为 D1 三层隔离预留：未来多用户 = 每用户独立工作区根 + 服务端按用户归组（本次不实现，接口预留 `WORKSPACE_DIR` 环境变量注入）。

### 4.8 与网页端的共享边界

| 层 | 共享 | 平台差异 |
|---|---|---|
| 业务协议 | event-registry 115 种事件、REST 路由、TaskEnvelope/run manifest | 无 |
| 前端代码 | client/ 同一构建产物 | desktop-capability.js 桥接模块 |
| 服务端 | server/ 同一代码 | 无（sidecar 与网页服务同源） |
| 平台能力 | — | electron/main + preload |
| 内置浏览器 | server/builtin-browser.mjs（网页端） | WebContentsView（桌面端） |

## 5. 实施里程碑

| 阶段 | 内容 | 验收门槛 |
|---|---|---|
| **E1 可用壳** | electron/ 骨架 + sidecar 管理 + 加载现有前端 + 打包出可安装包 | 双击安装 → 服务自起 → 全功能可跑（与网页端等价）；异常断电后重开可恢复 |
| **E2 平台桥** | preload 桥 + ipc-router + desktop-capability.js + 标题栏/托盘/更新 | 能力探测与降级正确；自绘标题栏；自动更新全流程演练一次 |
| **E3 原生浏览器** | WebContentsView 托管 + Agent 事件驱动 + 操作队列 + 下载/权限 | Agent 与人共用视图互抢符合预期；CDP 降级链可用（flag 门控） |
| **E4 分发打磨** | NSIS 签名、首启向导、工作区迁移、日志与崩溃上报 | 全新机器 10 分钟内完成安装到首次成功对话 |
| **E5 转正评估** | flag 转正、与三层隔离（D1）衔接设计评审 | 真实任务两周日常使用无阻断缺陷 |

依赖关系：E1/E2 不依赖服务端改造可立即启动；E3 需先行事件协议评审（Agent 浏览器事件复用 event-registry 扩展）；E5 前置阶段一转正轮（见后续路线计划）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| Chromium 安全补丁滞后 | 固定 electron 大版本跟踪安全公告；更新器随补丁版本发布 |
| 安装体积 ~150MB | NSIS 差分更新降低升级流量；依赖裁剪 |
| sidecar 与窗口生命周期竞态 | 单实例锁 + 探活就绪门 + 退出确认（4.1） |
| WebContentsView 与 React 布局同步抖动 | setBounds 节流（rAF 对齐）；降级链兜底 |
| 双壳功能漂移 | 桌面端不新增业务功能，仅平台能力；CI 增加桌面打包冒烟（E1 起） |
| 中文路径/编码 | 沿用项目既有正则路由与 UTF-8 约定；安装器与 userData 全 ASCII 路径测试 |
