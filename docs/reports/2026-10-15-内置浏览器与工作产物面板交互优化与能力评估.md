### 1.2 数据流（现状）

```
Agent 调 browser_* 工具 → CDP Input/Runtime/Page.screencast
  → broadcast(key, "frame|state|tabs|closed")（服务端内存 sessions/subscribers Map）
  → SSE /api/browser/stream（帧背压只留最新帧）
  → BrowserPanel setFrame → <img src=data:image/jpeg;base64>
对话侧并行：tool_start 事件 → ChatPanel 分发（name.startsWith("browser_")）
  → onBrowserActivity → App 自动开浏览器 aside（手动关闭后本轮回合阻断）
用户接管：面板输入 → POST /api/browser/input → 服务端 lease 仲裁（3min）
  → Agent 写操作与用户接管互斥
产物：run_finished/file_changed/artifact_published → 全局 SSE
  → artifactVersion++ → 产物面板拉取刷新（listRuns + published + acceptance）
```

### 1.3 状态同步机制

- 浏览器会话状态：服务端内存为唯一事实源（portFile+profile 跨重启进程复用）；前端唯一状态源为浏览器 SSE（state/tabs/frame/closed 四类事件），挂载时先 REST `/api/browser/state` 对齐再订阅。
- 接管归属（owner/lease）：服务端仲裁，前端只读展示。
- 产物：**前端拉模式**，refreshToken 由全局 SSE 白名单事件触发；发布/回滚后本地主动 refresh。

|---|---|---|---|
| P1 | 状态不同步 | 长任务执行期间产物面板始终显示"本轮暂未生成产物"：artifact 级刷新白名单只有 run_finished/file_changed/artifact_published，`artifact_staged` 不触发，产物在任务结束前不可见 | App.jsx:523；写入协调.mjs:378；工作产物面板.jsx:249 |

| P6 | 轻微不同步 | 接管倒计时不本地滴答：`secondsRemaining` 仅随服务端 state 事件下发，lease 空闲期间显示固定秒数 | 内置浏览器.mjs:668；内置浏览器面板.jsx:452-454 |

### 2.2 针对性优化方案（逐项）

| # | 方案 | 改动点 | 预期效果 |
|---|---|---|---|
| O-P1 | 产物渐进可见：`artifact_staged` 事件加入刷新白名单，staged 产物以"待确认"态进入产物列表（带阶段徽标），发布后转正式态 | App.jsx 白名单 + 工作产物面板.jsx 列表渲染态 + runs/artifacts 读取接口暴露 staged 项 | 长任务中产物实时可见，消除"盲等" |

## 3. 任务 2：内置浏览器全维度能力评估

### 3.1 六维度评估结论

| 维度 | 现状评估 | 评级 |
|---|---|---|
| 渲染性能 | CDP `Page.screencast` JPEG 帧流 + 服务端背压只留最新帧（防洪水），前端 img 直渲；无虚拟化开销 | ★★★★☆ |
| 资源加载速度 | **零依赖**直连 CDP（无 Playwright/Puppeteer，包体与启动无额外负担）；Edge/Chrome 复用 portFile+profile 避免重复冷启动 | ★★★★☆ |
| 多页面兼容性 | 浏览器级 CDP + `Target.attachToTarget(flatten:false)` 支持多 Tab（tabs 事件同步）；无 per-tab 视觉预览 | ★★★☆☆ |
| 功能完备度 | 10 工具覆盖打开/交互/快照/截图/Tab 管理；缺下载管理、Cookie/存储、iframe 内交互、整页截图、历史记录 | ★★★☆☆ |
| 操作便捷性 | 用户接管 lease 3 分钟自动回收、Agent/用户写互斥；缺地址栏直达、常用站点、视口模拟 | ★★★☆☆ |
| 安全防护能力 | lease 仲裁防 Agent/用户写冲突；缺域名白名单、下载文件处置策略、URL scheme 过滤的显式声明 | ★★★☆☆ |
