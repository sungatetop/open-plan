## 二、评审发现问题与修正决定（实施前必须采纳）

### N1【阻断级】F2 与硬约束冲突
- **问题**：计划 F2「直接替换 60 处原生 alert/confirm」属于新优化能力，违反硬约束「所有新优化能力必须置于 feature flag 之后，默认关闭以保证基线行为零变化」。
- **修正**：新建 `notify.error()/askConfirm()` 统一入口——flag `OAW_FLAG_FEEDBACK_V2`（默认关）**关闭时回退调用原生 alert/confirm（基线行为逐字节一致）**，开启时走 toast/confirmDialog。原生调用点收敛至 Feedback.jsx 单文件白名单。
- **验收改写**：client/src 中 `alert(/confirm(` 调用点归零（Feedback.jsx 白名单除外）；flag 开启→应用内反馈链路可用；flag 关闭→行为与基线一致（抽测 5 处高危点：删除会话/清凭据/回滚产物/删图层/删供应商）。

### N2【范围调整】F3 Modal 基座迁移推迟
- **问题**：SessionSidebar 3 类自研弹窗与 MapPanel 8 处 overlay 迁移至统一基座，在 flag 门控下需维持双实现，成本/收益倒挂；且旧弹窗本身已是应用内实现（非原生弹窗），紧迫度低于 P0-1。
- **修正**：本轮**不迁移**、不建空壳基座（避免死代码）；Modal 统一与旧弹窗迁移并入「flag 转正轮」。

### N3【前提修正】G12 性能基线降级
- 无 CI（已核实），G12「纳入 CI」降级为本地回归脚本（`test:map-perf`），随 GIS 批次交付。

### N4【利好确认】回归基线现成
- test:browser / test:a11y（无障碍与窄屏）/ test:motion / test:artifacts / test:first-token-latency 直接覆盖本轮批次 1-3 的回归面，验收可执行性强。

### N5【提交策略】工作区既有内容一并梳理
- 已暂存的 3 份评审文档 + 2 个动效演示 HTML + T3 两文件优化 + 未跟踪计划文档：评审文档与 T3 优化先行独立提交（评审+性能优化语义），动效演示 HTML 归入文档类提交；本轮实施改动独立提交。
