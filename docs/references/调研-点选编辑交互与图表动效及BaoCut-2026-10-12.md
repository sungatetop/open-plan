# 深调研：点选编辑交互 / 图表动效 / BaoCut —— 对照「规聚 · OpenPlan」现状

- 日期：2026-10-12
- 触发问题：① agent 生成的 PPT/HTML 能否在预览页**点击选中要素送进对话**？Claude 现在直接编辑 PPT/HTML 做到哪一步？② 怎么复现"让数据图表动起来"？③ "baoyu cut"是什么？
- 方法：两路专项网络调研（元素级编辑交互、动效能力）+ 本仓库实码盘点；官方原文均附 URL。**【实测】**=已在本仓库核对代码；**【官方原文】**=已抓取官方页面；**【子代理】**=子代理抓取；**【建议】**=工程判断。

## TL;DR

1. **"点选元素 → 进对话"在 Claude 已是产品化的成熟范式**，且以**评论（comment）+ "Send to Claude" 勾选**为主形态（Claude Design / Slides / Docs / Claude Tag 页面全部如此）；**Claude Science 是完整版**：选中文本/点图上一点/点 HTML 报告元素 → 存评论 → 随下一条消息连"文件名+引文+备注"一起发给 Claude，甚至可 "Ask" 分叉出 side chat。**Cowork 内置浏览器有真正的元素拾取器 "Select element"**（把元素+样式+截图送给 Claude，2026-09-10 changelog 实证）。
2. **画布直接编辑也已产品化**：Design 可拖拽/缩放/对齐/直接改文字/用 Claude 生成的滑杆调间距与颜色；Slides 支持对象级键盘编辑（Tab 逐对象、方向键移动、直接改文字）；Docs 支持"高亮文本 → Edit with Claude"。**但布局对象（母版定位的）不可手拖**——官方明说 "Ask Claude to move it"。
3. **你不需要从零做**：规聚**已经有这套交互的骨架**——`DocViewer` 的标注模式已能"选中文本 → 意图输入 → 作为 [选区上下文] 注入对话"【实测 client/src/components/DocViewer.jsx:498】，`DocxViewer` 同样有选区浮层"批注并注入"【实测 DocxViewer.jsx:716】；ChatPanel 已有 `insertContext()` 的选区上下文协议【实测 ChatPanel.jsx:1171】；deck-stage 已给每页打 `data-screen-label`（注释流预留）与 `data-om-validate=no_overflowing_text,no_overlapping_text,slide_sized_text`（溢出/重叠校验预留）【实测 designs/规聚-10分钟汇报/deck-stage.js:72-74】。**缺的只是"点元素"这个动作本身**（现在是"选中文本"，不是"点图形/图表/整块"）。
4. **图表动起来：官方路线与你的路线恰好互补。** 官方唯一"让图表动"的能力是 **Claude Motion**（Team/Enterprise beta，**代码驱动**动画化 text/charts/shapes/images，导出 MP4，不是视频生成模型）；而**官方 pptx skill 全程零动画**（连 animation/transition/timing 三个词都不出现），PowerPoint 插件也**明确无动画**，"原生图表保持可编辑"是官方底线。也就是说：官方负责"生成可编辑静态图表"，"让它动起来"这块**空白正是你可以做出的差异**。
5. **落地配方三件套（建议）**：
   - **HTML 演示版**：`data-chart` 声明式图表 + **ECharts 为主力**（入场动画开箱即用）/ 纯 CSS+SVG 兜底（零依赖、打印可靠）；挂到 `deck-stage` 已有的 **`slidechange` 事件**上重播，与 `data-anim` 的 `--i` 延迟阶梯共用；离线库落地到 `assets/`，CDN 回退（guizang skill 的 `motion.min.js` 已是"本地+CDN 双保险"先例）。
   - **PPTX 交付版**：低风险注入 `p:transition`（页级转场）或嵌入 MP4/GIF；**不要碰 `p:timing` 主时间轴**（交叉引用错就会让 PowerPoint 报文件损坏，官方 validate.py 不覆盖 timing 语义）。
   - **双产物策略**：HTML 演示版（动画/演示）+ PPTX 交付版（原生可编辑图表），与你现有 `pptx-export.json` 截图导出管线完全同构。
6. **"baoyu cut" = 宝玉的 AI 视频剪辑工具 BaoCut**（`JimLiu/baocut`，baocut.com）：以**可编辑时间线**为中心的 AI 视频 Agent（转录/字幕/翻译/配音/剪口播/短视频切条，动态图形代码生成），四入口（桌面/CLI/MCP+skill/Web）。**你本机没有装**，也**不属于 baoyu-skills 技能库**（那 22 个技能里无 cut 类）。对本项目是"视频产物能力"的独立启发，非直接组件。

## 一、Claude 的"点选元素 / 直接编辑"能力现状（逐个产品核实）

### 1.1 明确结论表

| 产品 | 点选元素→送进 Claude？ | 直接在画布编辑？ | 关键原文 |
|------|----------------------|----------------|---------|
| **Claude Design** | **是**（点画布元素→**内联评论**→带 "Send to Claude" 勾选→作为请求发给 Claude） | **是**（拖拽/缩放/对齐、直接改文字、Claude 生成的间距/颜色滑杆） | "Comment on any element, edit text directly, or use the adjustment sliders Claude creates to tune spacing and color."（claude.com/product/design）；"Inline comments let you click directly on a specific part of the canvas and request a targeted change."（14604416） |
| **Claude Slides** | **是**（评论可落在页**和页内每个 object** 上） | **是**（对象级：Tab 逐对象、方向键移动、Return 进文本框编辑） | "Press Tab to move to what you want to comment on. In a deck, that's the slide and then each object on it."（17457950） |
| **Artifacts 文档** | **是**（高亮文本 → **"Edit with Claude"** → Claude 在标记处直接改） | **是**（模板产物直接编辑） | "highlight the text you want changed, click 'Edit with Claude'… Claude makes the edit where you marked it, so you don't have to describe which section you mean."（17153992） |
| **Claude Science**（最完整） | **是**（选中文本 / 点图上一点 / **点 rendered HTML 报告里的元素**→评论→**随下一条消息发送**，携带 filename+quoted selection+note；可 "Ask" 分叉 side chat） | 评论不直接改，Claude 改 | "click a point on an image or figure; or turn on Comment and click an element in a rendered HTML report."；"Pending comments… are sent with your next message."（claude.com/docs/claude-science/comments.md） |
| **Claude for Google Workspace** | **是**（选区感知："see which text, cells, or slides you've selected"） | **是**（in place 修改 + 审批卡） | "select text, cells, or a slide first to point Claude at a specific part of the file."（16951679） |
| **Claude for PowerPoint** | **部分**（可证到 **slide 级**："Select a slide and tell Claude what to change"；**shape 级选区传递未能验证**） | **是**（原生可编辑图表/图形、保留母版与样式） | "Claude can target individual slides or elements."（claude.com/docs/office-agents/powerpoint） |
| **Cowork 内置浏览器** | **是（元素拾取器）** | — | changelog v1.52386.0（2026-09-10）："elements picked with **'Select element'** reaching Claude without their styles or with a screenshot of the wrong part of the page"（claude.com/docs/cowork/changelog） |
| **Claude Tag（Slack）** | **是（页面局部评论）** | — | "start a comment on the part you want changed… when the comment asks for a change, it edits the page and publishes the update to the same link"（claude.com/docs/claude-tag/…/create-artifacts.md） |
| 聊天内自定义可视化 | **是** | — | "clicking inside a visual sends a follow-up prompt to Claude (for example, 'drill into Q3')"（13979539） |
| 旧 Canvas | — | — | **不存在（现状）**：帮助中心无 Canvas 编辑器文章，release notes（2025-08～2026-10）零次提及；近似能力已被 artifacts "Edit with Claude" 与内联评论取代。别再对标它。 |

**一句话总判断**：Claude **没有**跨产品统一的"预览里点选 → 送进主对话"通用交互，但**已收敛出三个可复现的官方范式**：① **内联评论 + Send to Claude**（最主流）；② **选区/评论随下一条消息发送并回传引文**（Science，与你的需求最贴近）；③ **拾取器把 DOM 元素连同样式+截图送给模型**（Cowork 浏览器，工程上最像"框选预览元素当上下文"）。

### 1.2 关键机制细节（可直接抄的设计）

- **"Send to Claude" 勾选框**：Design/Slides/Docs 的评论框里，"A 'Send to Claude' checkbox before the send button sets whether the comment also goes to Claude as a request."（17457950）——**评论与"发给 Claude"是两件事**：评论可以只是给人看的批注，勾选后才变成 agent 请求。这与你现有 `DocViewer` 的 `comment` / `agent` 双模式**完全同构**【实测 DocViewer.jsx:444-506】，说明你的方向是对的，可以放心把它产品化。
- **评论可回复、带作者标记**："Each comment has a marker on the artifact, named with the comment's author."；"The posted comment opens with focus in its reply field."（17457950）
- **已知缺陷（官方原文，值得提前规避）**："comments can disappear before Claude reads them"（14604416）——所以官方建议"评论没被读到就直接贴到聊天框"。**契机**：规聚已有"选区上下文直接注入输入框"的路径，天然规避这个坑；建议以"注入输入框"为主、"评论锚点"为增量。
- **批处理的 pending 模式**（Science）："Saving a comment doesn't send it. Pending comments appear above the message box and are sent with your next message."——**多条选中攒着一起发**，比逐条打断更符合汇报场景。
- **布局对象不可手拖**："If the arrow keys don't move an object, it's part of the slide's layout… Ask Claude to move it."（17457950）——对应你的"agent 产物 vs 手改"边界：**结构归 agent，微调归用户**。
- **审批卡**（Google Workspace）："In the default 'Ask before edits' mode, each change appears as an approval card with a summary and Claude waits for your approval."——与规聚已有的 ask_user 卡片/验收状态是同一套语汇。

### 2.2 差距清单（按你的目标）

**目标 A：预览页点选元素 → 进对话**

现状能"**选中文本**"，不能"**点元素/框选区块**"。补齐三件：
1. **元素级拾取**：HTML 预览 iframe 内注入拾取脚本（`click` 捕获 + `elementFromPoint`），产出选择器路径（如 `section[data-screen-label="07"] .kpi:first-child`）+ 元素快照（tag/文本/该元素 boundingRect）——参考 Cowork "Select element" 的"元素+样式+截图"三件套。
2. **锚点消息格式**：把现有 `[选区上下文]` 升级为结构化引用（如 `[元素上下文]{file, slide:7, label, selector, tag, text, box}`），让 agent 能精确定位（deck-stage 的 `data-screen-label` 现成可用）。
3. **视觉反馈**：hover 高亮 + 点击后固定描边（复用 CommentMarker 的批注视觉语言），支持"多条待发"（对齐 Science 的 pending 批处理）。

**目标 B：图表动起来**

现状：模板里是静态 Chart.js + CDN。补齐：
1. `chart-runtime.js` + `data-chart` 声明式（详见 §3.2）；ECharts 本地化，CDN 回退。
2. 与 `slidechange` / `--i` / reduced-motion 三处既有钩子接线（**必须**，否则破坏 `动效治理测试.mjs`）。
3. 导出等待：截图导出前等动画稳定（1-1.2s）并 `chart.resize()`（guizang 技能已有经验句："截图前等入场动效稳定(约 1-2 秒)"）。
4. PPTX 交付侧走 §3.3。

**目标 C：直接编辑 PPT/HTML**

短期不必做完整画布编辑器（成本高、且官方布局对象也不可手拖）。**性价比最高的是"文本级直改"**：deck-stage 注释已点名"静态 HTML 才能让用户点标题直接改字；用 React/循环生成的幻灯片每次微调都得走一条聊天消息"【实测 :79-85】。规聚模板正是静态 HTML——**建议先做"点文本 → 就地编辑 → 回写文件"的最小闭环**，再做图形拖拽。

### 3.2 HTML 演示版：图表动画配方（建议）

**技术路线对比**：

| 路线 | 入场动画 | 体积 | 与现有体系兼容 | 建议 |
|------|---------|------|--------------|------|
| **ECharts** | 内置最强（`animationDuration/animationEasing/animationDelay`，折线生长/柱状拔起/饼图展开开箱即用；`setOption` 增量更新带动画） | 全量 ~1MB，按需裁剪 ~300KB | init 时 `animation:false`，slide 进入再重设 option 重播 | **主力** |
| Chart.js | 内置但偏简单 | ~200KB | 好（现有模板已用） | 轻量单图 |
| D3 | 自由度最高、代码量最大 | ~280KB | 好（`llm-wiki/deps/d3.min.js` 已有本地副本） | 定制视觉 |
| **纯 CSS+SVG** | 折线 `stroke-dashoffset`、柱状 height 过渡、饼图 `stroke-dasharray`、数字 count-up | **0 依赖** | **最好** | **兜底/离线/打印** |

**声明式架构**（与 `data-anim` 分工：`data-anim`=元素入场，`data-chart`=数据入场）：

```html
<section class="slide" data-label="经营数据">
  <div data-chart='{"type":"bar","categories":["Q1","Q2","Q3","Q4"],
       "series":[{"name":"客运量","data":[42,58,73,96]}],"animation":"growUp"}'
       style="--i:2;height:520px"></div>
</section>
```

`chart-runtime.js` 单文件职责：
1. 解析 `data-chart` → 探测 `window.echarts`（**本地文件优先，缺失时降级纯 SVG 渲染器**，沿用 guizang 的"本地+CDN 双保险"模式）；
2. `animation` 关键字映射：`drawIn`（折线描线）/ `growUp`（柱状拉起）/ `radialIn`（饼图展开）/ `countUp`（数字滚动）；
3. 订阅 deck-stage 的 **`slidechange`** 事件（`e.detail.slide`），对进入页内 `[data-chart]` 先 `clear()` 再重播；
4. 与 `--i` 阶梯共用：`animation-delay: calc(var(--i,0)*80ms)`，让图表排在文字之后；
5. 遵循 deck-stage 既有约定"**终态为基础样式、动画从隐藏开始**"，用 `@media (prefers-reduced-motion:no-preference)` 门闩；
6. **纳入 `scripts/动效治理测试.mjs` 的统一断言**（系统 reduced-motion + 产品关闭动效 + 历史回放不重播）。

**导出注意**：canvas 图表在 deck-stage 的 `transform: scale()` 容器里会模糊——按 `devicePixelRatio` 初始化并在进入后 `resize()`；截图导出（现有 `pptx-export.json` 流程）**每页等动画稳定 1-1.2s 再截**（guizang 技能已有此经验）。

### 3.3 PPTX 交付版：动效取舍（建议）

| 方案 | 复杂度 | 风险 | 建议 |
|------|-------|------|------|
| 注入 `p:transition`（页级转场，如 fade/push） | 低 | 老版本 PowerPoint/WPS 兼容差异 | **推荐**（性价比最高） |
| 注入 `p:timing` 图表"按系列"入场 | **高** | 时间轴交叉引用错→PowerPoint 判损坏；**官方 validate.py 不覆盖 timing 语义** | 谨慎：仅做"按系列"单一形态 + 真机逐页回归 |
| 嵌入 GIF / MP4 | 中 | GIF 256 色/体积；MP4 依赖播放环境 | **推荐**（动效主力） |
| **双产物**：HTML 演示版 + PPTX 交付版 | 低（复用现有管线） | 需数据同步 | **强烈推荐**（与现状最契合） |

**交付底线**（借官方原则）：**"Keep charts native"**——交付版里图表仍应是 PowerPoint 原生可编辑对象（走你已有的 pptxgenjs `addChart`），动效以转场或叠加媒体呈现，**不要为了动画把图表降级成图片**。

### 3.4 三步落地顺序（建议）

1. **P1（最小闭环，1 个迭代）**：把 `chart-bar.html` 这类现有图表**从 CDN 换成本地 ECharts + 加 `growUp` 入场**，验证 `slidechange` 重播 + reduced-motion + 截图导出三处都对；同步把 `动效治理测试.mjs` 扩展一条断言。
2. **P2（模板级推广）**：`data-chart` 声明式 + `chart-runtime.js` 抽成 `templates/opendesign/html-ppt/assets/` 下的共享资产；把 31 个 single-page 布局里的图表页统一迁移；`data-anim` 与 `data-chart` 的延迟阶梯统一。
3. **P3（预览页交互）**：元素拾取 + `[元素上下文]` 锚点 + 多条待发；PPTX 侧补 `p:transition`。

## 四、"baoyu cut" 是什么：BaoCut

**结论**：不指向任何 `baoyu-cut` 技能或仓库（GitHub 搜索 0 结果），实际是**宝玉（JimLiu / @dotey）出品的 AI 视频剪辑工具 BaoCut**——仓库 `github.com/JimLiu/baocut`（771★，TypeScript，2026-07-13 创建、2026-10-12 仍在更新），官网 `baocut.com`。官方英文简介含 "…transcribe, subtitle, translate, dub, **cut** and animate"，这就是"baoyu 的 cut 工具"的由来。**你本机未安装**，也不属于 baoyu-skills。

**它是什么**：以"**可编辑视频**"为中心的 AI 视频 Agent——不是渲染完就结束，所有结果都落在可继续编辑的时间线上。功能：转录（本地 Whisper/Qwen3-ASR，词级时间戳）、字幕（原文/译文/双语）、配音（人声分离 + 逐句合成）、**剪口播**（去口癖/长停顿/重录/口误，原片不动）、章节/摘要/标题/短视频切条、从提示词做视频（24 模板）、**动态图形以代码生成（HTML 合成）**、图片生成。导出 MP4 / SRT / 文稿 / 音轨 / `.baocut` 包。

**四个入口（同一 Runtime）**：桌面应用（Electron，Mac DMG / Windows CPU-CUDA-Vulkan，**未签名**，需自备 ffmpeg）、CLI（`baocut`，npm `@baocut/cli`）、**MCP 服务 + skill**（`baocut skill install` / `baocut mcp install`）、Web 客户端。自带引擎：Claude Code、Codex CLI 等。

**许可**：source-available（BaoCut Community License 1.0）——**个人/学习/研究免费，商业内容创作免费且无水印**；售卖软件、改名换皮、托管服务、嵌入商业软件需另购商业许可。**不是 OSI 开源**。
