# 规聚产品基线与后续开发路线

## 1. 当前基线（2026-10-19 测量）

- **版本**：v0.11.55（变更日志最新已发布），其后 10 批 Qoder 对标优化已完成开发、全部 opt-in 默认关。
- **技术栈**：React 18 + Vite 5 / Express 5（:3002）/ Pi SDK 1.1.0 / Node ≥ 22。
- **能力**：六大域齐备（文档办公/AI 协作/知识库/地图 GIS/模板库/记忆与智能），需求定义见 `REQUIREMENTS.md` R1-R14。
- **质量**：CI 16/16 全绿（Node 22）；`npm run verify`（语法+构建+40 项 API 冒烟）为提交门槛。
- **文档基线**：`DESIGN.md`（设计目标/架构）、`REQUIREMENTS.md`（R1-R14）、`docs/module-design/架构总览.md`、`docs/decisions/BRD-001~007` 已对齐本基线——**此前的文档与 v0.8.34 基线漂移问题已消除**。
- **结构基线**：代码全英文命名；文档入 `docs/` 分类目录；脚本分区（根=测试、ops=运维、reporting=汇报、tools=数据工具）。

## 3. 路线规划

### 阶段一：转正与稳定（近期）

- 目标：把"已完成开发但默认关"的能力安全地变成默认体验。
- 范围：T1 → T2 → T3 → T4（顺序执行，每项独立可回滚）。
- 期间冻结新功能开发；CI 保持 16/16 全绿为硬门槛。
- 收口标准：runtimeFlags 中 Qoder/PI-SDK 系列开关全部转正或明确废弃，flag 清单归零冗余。

### 阶段二：桌面端与多用户（中期）

- 前置：阶段一收口。
- 范围：D1 三层隔离 → D2 Electron 一体化 TS 重构（R0 等价壳起步，按域绞杀推进）→ D3 内网灰度。
- 设计约束：Electron Node 侧即后端（BRD-009）；共享核心不复制业务（BRD-002 原则）；A2 路由拆分与后端 TS 化批次合并推进。

### 阶段三：功能补全与治理深化（中远期）

- 范围：F1-F5 按域穿插迭代；A1/A3/A4 治理项持续。
- SaaS 多租户与混合部署：仅在 D3 灰度成功后启动评估。

## 4. 迭代纪律（沿用既有约定）

1. feature 分支 → `npm run verify` 通过才提交 → 更新变更日志 → 合入打 tag（AGENT.MD）。
2. 一切新行为挂 flag 默认关（BRD-003）。
3. 新增事件先注册（BRD-005）；新文档入 `docs/` 分类目录并带 frontmatter。
4. 每阶段收口输出验证报告到 `docs/reports/`，结论回写本文档状态。
