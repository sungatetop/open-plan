# 规聚（Open Plan）上线部署实施计划

> **面向执行者：** 本计划自包含，按顺序执行即可；无需补充信息。每个任务带 `- [ ]` 复选框，完成即勾选并记录到变更日志.md。配套规格：`docs/多用户隔离与桌面端路线梳理.md`（本计划的依据，编号沿用其"落地顺序清单"）。
> **团队假设：** 1 后端 + 1 前端/桌面 + 0.5 测试（可兼任）。时间以工作日（D）计，按此人力估算；人力变化时按比例伸缩，但**阶段顺序与质量门禁不变**。

**目标：** 把规聚从单用户本机应用升级为"内网多用户版 + Tauri 桌面端 POC"，通过五层测试验证后灰度上线。

**架构：** Express 单服务加鉴权中间件层；工作区目录模型改为 `workspaces/<userId>/<wsName>/`；Pi Runtime 按用户池化；Tauri 壳以 sidecar 方式复用现有 server + React 前端；`FEATURE_CLOUD` 开关决定装配云组件。

**技术栈：** Node 22 + Express 5 + Pi Agent SDK、React 18 + Vite 5、officecli、MapLibre GL、Tauri 2、Vitest（新增测试运行器）。

**基线：** v0.11.49（master=origin/main，`a30659c5`）。v0.11.48（`d5ceb480`）之后的工作区收口提交：`576cfe4a` 前端溢出修复、`b34257cc` 地图三重加载失败、`94921c6c` Windows 路径兜底、`09cb7494` 模型套餐 Tab、`af0d5367` 本计划入库、`a30659c5` 发布记录。

| **集成** | 登录→会话→产物→凭据隔离链路；officecli/map 工具过闸；staging 一致性 | 脚本化（`scripts/测试-*.mjs`，node 直跑输出 PASS/FAIL）：双用户互查 404、跨工作区写拒绝、Agent 写读闭环、rebuild-tiles 恢复 | 本机 + 1 台干净 Win11 VM（officecli 从零） | 单元准出 + 阶段代码合入 | 每脚本 PASS；VM 上零预置跑通 |
| **系统** | 双用户并发、公平调度、沙箱、桌面包全链路、长跑（Agent 连续任务 1h） | 并发脚本 + 长跑脚本 + 手工探索（2h 自由测试）；日志无未捕获异常 | 内网目标机（与生产同配）+ VM | G1–G3 通过、桌面包可安装 | T5.1/T5.2 指标全达标 |
| **验收** | UAT 场景 + 部署演练（含回滚演练） | 按冻结规格场景清单逐条打勾；回滚 = 上一版备份包恢复 <10 分钟 | 生产环境 | 系统准出 + 安全自查高危=0 | 验收报告签字（你） |

**通用异常处理机制**：任何层级失败 → 修复 → **该层级全量回归重跑**（不只重跑失败项）；单元缺陷不得到集成复现即关闭；生产类缺陷必须补一条等价回归用例入库。缺陷分级：P0 阻断（当日修）/ P1 严重（48h）/ P2 一般（版本内）/ P3 轻微（记录）。

**质量门禁（G0–G5）**：每阶段末执行，未过不得进入下一阶段；门禁项 = `npm run verify` 全绿 + 本阶段"验证"小节全过 + 变更日志已更新 + 无 P0/P1 未关闭。G4 桌面门 = 干净 VM 安装四项全过。G5 上线门 = 验收报告签字。**任何人可执行**：逐条跑命令对表格打勾。
