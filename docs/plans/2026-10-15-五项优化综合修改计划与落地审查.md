## 二、落地要求审查（逐项核对结论）

### A. 发现的冲突与修正（审查产出，必须在实施前采纳）

| # | 问题 | 定性 | 修正决定 |
|---|---|---|---|
| A1 | GIS 方案 G2 原文提出 `better-sqlite3`，**违反「零新增 npm 依赖」硬约束** | 阻断级 | 改用 Node 内置 `node:sqlite`（Node≥22.5 零依赖）；运行环境不满足则降级为 CSV/GeoJSON 管道预处理。如坚持 better-sqlite3 需显式豁免约束 |
| A2 | 交互八项中 O-P1/O-P2/O-P7/O-P8 与 B3/B5 均改变基线行为，原方案未统一挂 flag | 违反「feature flag 默认关闭」约束 | 已在批次 2/3 表格补齐 flag 列（`OAW_FLAG_*`，默认关）；O-P3 拆分：判定修正属缺陷修复直接改，徽标属新行为挂 flag |
| A3 | B4（浏览器 PDF 导出）与 G7（GIS 批量导出 PDF）能力重叠，两文档各自描述 | 冗余 | 合流：B4 建 PDF/整页截图底座，G7 复用底座做批量队列，避免两套 PDF 实现 |

| A5 | client 无测试框架，任务5 验收标准中「走查」类条目不可执行 | 验收不可测 | 可测化：build 通过 + grep 断言（alert 归零 / aria-label 覆盖 / size 栅格）+ 固定手工走查清单（四档宽度 × 三面板） |
| A6 | 60 处 alert/confirm 一次性替换回归面过大 | 实施风险 | F2 强制分文件渐进替换，每文件替换后立即 build + 该文件操作路径手工回归；SessionSidebar/SettingsPanel/KnowledgeBase 三个高频文件先行 |
| A7 | G12「纳入 CI」前提是项目已有 CI，现状未确认 | 前提未验证 | 实施前先确认 CI 现状；无 CI 则降级为本地回归脚本 `test:map-perf` |

### B. 验收标准可测性核对（全部通过修正后可测）
- 量化达标类：dispatch<1s（复测脚本）/ 缓冲区 1 万要素 ≤2s / 5 万要素 ≥30fps / 3×3 队列完成 — **可测**
- 行为断言类：grep 归零 / flag 默认关 / Esc 可关 / staged 可见 — **可测**
- 体验类：智能切页不抢用户主动权、徽标可达 — 拆为「手动锁定 10s 内不抢占」等行为断言 — **可测**

### C. 风险登记（Top 3）
1. **F2 大面积 UI 回归**（中高）：缓解 = A6 渐进替换 + 高频文件先行。
2. **G1 手写几何算法正确性**（中）：缓解 = 与 turf 参考实现抽检对比用例（矩形/多边形/自相交边界），先缓冲区后叠加。
3. **O-P1 staged 可见对既有产物消费方的扰动**（中）：缓解 = flag 默认关 + 产物面板渲染态单独灰度验证。

### D. 工作量与顺序结论
- 批次 1（反馈基座）与批次 2（面板联动）**可并行**，无文件争用（F2 触达 ChatPanel 时注意与 O-P5/O-P8 同文件改动合并提交）。
