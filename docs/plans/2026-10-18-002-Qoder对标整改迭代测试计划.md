## 3. 测试分层与执行流程

### 3.1 四层结构

| 层 | 内容 | 手段 | 通过标准 |
|---|---|---|---|
| **L1 静态** | 构建 + 存量回归 | `npm run build`、`npm run verify`、68 个 `test:*` | 构建成功；全部通过 |
| **L2 源码级断言** | 修改点的结构/契约断言 | 新增 `scripts/*测试.mjs`（纯 Node，无浏览器） | 用例全绿 |
| **L3 浏览器端到端** | 真实交互场景 | Playwright（复用上级文档 §3 模板骨架） | 场景表全过，附截图/JSON 证据 |
| **L4 兼容与性能** | 浏览器矩阵、分辨率、性能基线 | Playwright + `performance` API + 服务端计时 | 阈值达标 |

### 3.2 每阶段执行流程（固定五步）

1. **准备**：`git pull` 至该阶段分支；`npm run build`；启动服务（`npm start`）；确认 `officecli --version` 与工作区可用。
2. **L1 回归**：串行跑该阶段映射的 `RG` 分组（见 §5）→ 记录失败项，与 M0 基线比对，区分"新引入"与"已知遗留"。
3. **L2 专项**：跑本阶段新增的 `TC` 脚本 → 全绿方可继续。
4. **L3 端到端 + L4 兼容性能**：跑本阶段的 `TC`/`ED`/`CP`/`PF` 场景 → 逐条勾选，留存截图或 JSON。
5. **归档**：把结果写入本文档 §12 报告表 + `变更日志.md` 阶段小结；未过项进入 §10 缺陷闭环。

### 3.3 执行顺序约束

- `RG` 必须先于 `TC`：存量回归失败会污染专项结论。
- 涉及事件注册表的改动（TC-M1-02/03、TC-M2-02/04、TC-M4-03、TC-M5-01）：必须以 `test:pi-iteration` 作为前置门禁。
- `CP`/`PF` 放在阶段末尾：它们耗时最长且依赖前序步骤已通过。

## 10. 缺陷分级、上报与闭环规则

### 10.1 缺陷等级定义

| 等级 | 定义 | 示例 | 响应时限 | 修复时限 |
|---|---|---|---|---|
| **P0 阻断** | 数据损坏 / 功能不可用 / 结果错误且无提示 | 中断排空导致内容丢失；写回保护失效导致源文件被未确认覆盖；坐标越界未被阻断 | 立即 | 当班内 |
| **P1 严重** | 主链路功能异常但有绕过路径 | 配额拒绝后无法恢复；执行句柄中断后无法再执行；对象栏分组与后端数据不一致 | 4 小时 | 1 个工作日 |
| **P2 一般** | 体验缺陷 / 非主链路异常 | 退避抖动未完全消除重连集中；阶段条状态延迟；暗色下局部对比度偏低 | 1 个工作日 | 3 个工作日 |
| **P3 轻微** | 文案 / 视觉细节 | 分组标题措辞；空态文案；图标尺寸偏差 | 3 个工作日 | 下个迭代 |

### 10.2 上报规则

1. **发现即录**：统一在缺陷清单登记（编号 `BUG-<阶段>-<序号>`），字段：用例编号 / 环境 / 复现步骤 / 实际 vs 预期 / 证据（截图或 JSON）/ 等级 / 责任人。
2. **P0 即时上报**：当场通知责任人与阶段负责人，**暂停**该阶段后续用例执行，优先修复。
3. **P1 当日上报**：每日站会同步；若影响关键路径，触发修改计划 §7.1 风险预案 R0。
4. **P2/P3 批量上报**：阶段末统一评审，决定"本阶段修 / 下阶段修 / 不修（需写明理由）"。
5. **回归要求**：任何修复必须附带**回归验证证据**（原用例重跑通过 + 相关 `RG` 分组重跑通过）。

### 10.3 闭环规则

```
发现 → 登记(定级) → 指派 → 修复 → 回归验证 → 关闭
                    ↓                        ↓
              无法复现/不修          回归失败 → 重开(P0/P1 升级)
```

- **关闭条件**：原用例通过 + 相关 `RG` 分组通过 + 证据归档。
- **回归失败**：缺陷重开；连续两次回归失败则等级升一级。
- **级联影响**：改动涉及事件注册表 / 执行句柄 / 流连接三个核心模块的缺陷，关闭前必须重跑 `test:pi-iteration` 与 `test:sse-protocol`。
- **周报**：每周统计"新增 / 关闭 / 存量（按等级）"，写入阶段小结。

## 13. 附：L3 端到端脚本骨架（复用上级文档模板）

```js
// 1. 启动 chromium（复用本机 ms-playwright）
// 2. 打开 http://127.0.0.1:3002
// 3. 进入目标能力（对话 / 地图 / 工作流）
// 4. 触发场景（发送指令 / 切换主题 / 拖拽 / 缩放窗口）
// 5. 等待终态：轮询关键 DOM 标记或服务端接口
// 6. 读取事实：
//    - 服务端接口（如 GET /api/agent/events/state、GET /api/runs/:id）
//    - 事件：读 .oaw/runs/<最新>.json 的 events
// 7. 断言并截图
```

**关键技巧（沿用既有经验）：**
- 判断工具是否真被调用：读 Run JSON 的 `tool_start` 事件，**不要**只看 UI 工具卡。
- 图层/底图变化判定：对比 `/api/map/project?name=zhejiang-map` 返回的 `style.layers` id 集合。
- 分辨率切换：用 `page.setViewportSize()` 而非缩放，避免 DPR 干扰。
- 控制台报错采集：监听 `page.on('console')` 与 `page.on('pageerror')`，作为 `CP` 类用例的附加判定。
